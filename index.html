Arquitectura de la librería

Los 57 elementos documentados en este sitio no son 57 archivos TSX. Son variantes y estados de 12 componentes. Cada componente agrupa elementos relacionados bajo una sola prop variant.

ℹ
Regla de importación única. Toda la librería se importa desde @/components/ui/. Ningún componente duplica funcionalidad de otro. Si algo no está en la librería, se agrega aquí antes de programarlo.

Orden de construcción recomendado

Algunos componentes dependen de otros. Respetar este orden evita retrabajos. Daryl debe completar cada fila antes de pasar a la siguiente.

1
_pjev-tokens.css
Variables CSS globales extraídas de globals.css. Bloquea todo lo demás.
Bloquea: todos
2
SiafButton.tsx
Primer componente. Se usa en todos los formularios y grids.
Bloquea: SiafPageHeader, SiafModal, SiafDataGrid
3
SiafInput.tsx + SiafSelect.tsx + SiafTextarea.tsx + SiafCheckbox.tsx
Controles de formulario base. Todos siguen el mismo patrón de estados.
Bloquea: SiafFormGroup, FM-03, FM-04
4
SiafBadge.tsx + SiafFormGroup.tsx
Utilitarios que se usan dentro del grid y los formularios.
Bloquea: SiafDataGrid
5
SiafToast.tsx
Migración de lib/toast.tsx existente. Solo se estandariza, no se reescribe.
Sin dependencias
6
SiafModal.tsx
Extensión de CancelModal.tsx existente con nuevas variantes.
Requiere: SiafButton
7
SiafDataGrid.tsx
El componente más complejo. Requiere todos los anteriores.
Requiere: SiafButton, SiafBadge, SiafToast
8
SiafCard.tsx + SiafPageHeader.tsx
Contenedores de layout. Se construyen al final porque envuelven todo lo demás.
Requiere: SiafButton
Cómo migrar una pantalla existente

Una vez que los 12 componentes existen, Cristian sigue este proceso para cada pantalla.

⚠
Regla de migración progresiva. No se migran todas las pantallas a la vez. Se migra una, se valida con Eunice, y se avanza. El orden recomendado es: primero los catálogos simples (CFG), luego Contabilidad, luego Presupuesto y Financiero. 
// PASO 1 — Eliminar el objeto COLORS o constantes de estilos locales
// ✕ Borrar esto:
const COLORS = { green: '#285847', ... }

// PASO 2 — Importar los componentes de la librería
import { SiafButton }   from '@/components/ui/SiafButton'
import { SiafDataGrid } from '@/components/ui/SiafDataGrid'
import { SiafBadge }    from '@/components/ui/SiafBadge'
import { SiafPageHeader } from '@/components/ui/SiafPageHeader'

// PASO 3 — Reemplazar botones inline
// ✕ Antes:
<button style={{ background: COLORS.green, color: '#fff', ... }}>Guardar</button>
// ✓ Ahora:
<SiafButton variant="primary" loading={submitting}>Guardar</SiafButton>

// PASO 4 — Reemplazar la tabla manual por SiafDataGrid
// ✕ Antes: 60+ líneas de <table><thead>... con estilos inline
// ✓ Ahora:
<SiafDataGrid
  columns={columns}
  data={rows}
  pagination={meta}
  onPageChange={load}
  loading={loading}
/>

// PASO 5 — Reemplazar badges de estatus
// ✕ Antes: objeto ESTATUS_BADGE con bg/color por página
// ✓ Ahora:
<SiafBadge variant={estatus.toLowerCase()}>{estatus}</SiafBadge>

// PASO 6 — Envolver en SiafPageHeader
<SiafPageHeader
  breadcrumb={['Contabilidad', 'Registro', 'Pólizas']}
  title="Pólizas contables"
  actions={<SiafButton variant="primary" icon={Plus}>Nueva póliza</SiafButton>}
/>
